# Backend

The backend is a FastAPI service in `backend/app/`. The frontend career graph uses the `/career-tree/*` API, whose AI and domain operations are orchestrated by LangGraph.

For the full project setup and environment variables, see the repository-root `README.md`. For a high-level request-flow overview, see `docs/ARCHITECTURE.md`.

## Main modules

- `app/main.py` — FastAPI application, authentication, rate-limit dependencies, request validation, and API routes.
- `app/career_workflow.py` — compiled LangGraph for career operations, including explicit branch validation/cache, context, generation, relevance, and tree-assembly steps.
- `app/career_tree.py` — career-tree initialization, on-demand branch generation, relevance checks, and tree updates.
- `app/career_chat.py` — conversational guidance, node explanations, and user-confirmed graph change proposals.
- `app/live_jobs.py` — validated live job searches through TheirStack.
- `app/state_manager.py` — account-scoped Supabase session persistence.
- `app/config.py` — environment-driven OpenAI and Supabase client setup.
- `app/rate_limiter.py` — shared Supabase/Postgres rate limiting.
- `app/utils/` — normalization and acronym helpers.

## Current API flow

The graph page (`frontend/src/app/graph/page.tsx`) calls the career-tree API through `frontend/src/lib/graphApi.mjs`:

- `GET /career-tree/session` — load the signed-in user's account-level graph session.
- `POST /career-tree/initialize` — initialize the tree from the user's stated or saved interests.
- `POST /career-tree/expand` — generate a selected interest's industries or an industry's roles.
- `PUT /career-tree/state` — save selected and expanded nodes.
- `POST /career-tree/reset` and `/career-tree/delete` — reset the tree or remove a node.
- `POST /career-tree/message` — continue the career-guide conversation.
- `POST /career-tree/explain` — explain a selected interest, industry, or role.
- `POST /career-tree/changes` — accept or reject a proposed graph/profile change.
- `POST /career-tree/jobs` — search live U.S. listings for a selected role.

Protected endpoints validate the Supabase bearer token, enforce shared per-user and per-IP limits, and access data using the caller's identity. Suggestions are generated on demand, tied to their originating interest path, and checked before saving. Job listings come from TheirStack; they are not generated by the model.

For expansion, LangGraph runs `expand` (validate the parent and resolve the cache), then either ends with the cached tree or runs `expand_context` -> `expand_generate` -> `expand_verify` -> `expand_apply`. Domain helpers in `career_tree.py` retain the prompts, parsing, relevance rules, stable node IDs, and detail limits. The direct `expand_tree()` helper uses the same steps for callers that do not invoke the graph. Other career operations still delegate to their existing domain functions.

Workflow state is temporary and local to one invocation; Supabase persistence stays in the API layer after successful completion. Failed steps propagate their existing errors without retries or partial saves. This graph does not add a cross-request queue or protect simultaneous edits from multiple tabs.

`GET /session/{session_id}` retrieves a saved session and remains useful for debugging or older saved sessions. `/health` is a liveness check; `/ready` checks Supabase reachability.

## Run locally

From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
PYTHONPATH=backend uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Alternatively, the root `Makefile` provides `make backend-dev`, `make backend-up`, `make backend-status`, and `make backend-down`.

Create the required local environment configuration as described in the root README. OpenAI, Supabase, and TheirStack features require their corresponding credentials. Never expose `SUPABASE_SERVICE_ROLE_KEY` or provider keys in frontend variables.

## Tests

Tests are in `backend/tests/`. Unit tests mock external services where appropriate; tests marked `integration` are kept separate.

Expansion tests exercise both the direct helper and LangGraph. Pre-refactor fingerprints check exact prompt messages and resulting trees for fixed model responses. Workflow tests also check node order, cache shortcuts, and that failures stop before tree assembly.

```bash
# Unit tests
PYTHONPATH=backend .venv/bin/pytest -q -m "not integration"

# Integration tests
PYTHONPATH=backend .venv/bin/pytest -q -m integration
```

GitHub Actions uses `backend/requirements-ci.txt` for its Python test jobs.

## Deployment notes

- Apply SQL migrations in `backend/migrations/` to Supabase, including the session ownership/RLS and shared rate-limit migrations.
- In production, set `APP_ENV=production`, the required Supabase settings, and exact HTTPS frontend origins in `CORS_ALLOWED_ORIGINS`.
- Keep the service-role key and provider API keys backend-only. Configure `FORWARDED_ALLOW_IPS` to trusted reverse-proxy addresses.
- Configure TLS at the hosting platform or trusted proxy. CAPTCHA, Supabase Auth protections, and WAF rules require provider-side configuration.
- `/ready` checks Supabase availability for the rate-limit store. OpenAI is not a readiness dependency.
